# Registrar Adapter Contract

The core Skill owns route selection, sequencing, evidence, and safety. A registrar adapter owns only the current provider-specific way to read or change nameservers, registrar-hosted DNS, and DS records. Hosting deployment and custom-domain binding remain Pages/Vercel responsibilities; authoritative records after cutover remain Cloudflare responsibilities.

## Required capabilities

Every adapter must expose or document these operations separately:

1. Identify the exact domain and registrar account without exposing account secrets.
2. Read current authoritative nameservers.
3. Read current DNSSEC state and parent-facing DS fields.
4. Read registrar-hosted DNS records before they are replaced or cleaned up.
5. Update nameservers to the exact provider-assigned set.
6. Disable or remove the old DNSSEC/DS state.
7. Add the exact new DS generated by Cloudflare.
8. Read back provider state after each mutation.

Each mutation returns the target domain, before value, after value, provider status, timestamp, evidence pointer, and rollback action. Browser screenshots may support the record, but public DNS is still required.

## Spaceship adapter

Spaceship is the only registrar route in `nemo-domain-launch` 0.2.0. Treat it as a live browser/provider adapter, not a promise that labels or click paths remain unchanged.

- Domain purchase, renewal, transfer, and paid upgrades are outside this Skill.
- Reuse the user's current authenticated session; never inspect Cookies, local storage, password fields, or recovery data.
- Resolve the exact domain from the live domain list before opening nameserver or DNSSEC controls.
- The official nameserver article was challenge-protected during the 2026-08-14 source review. Discover current controls at runtime and record their visible labels; do not hardcode an unverified permanent click path.
- Before changing nameservers, capture current nameservers, registrar-hosted DNS, and DNSSEC/DS state.
- Before deleting a parking record, save the full exact record. Delete only an authorized blocker matched by ID, type, name, and content; preserve the snapshot even when the UI calls it a default.
- After submitting nameservers or DS, read the provider confirmation and then verify the parent zone publicly. A success toast is not propagation evidence.
- If Spaceship automatically manages DNSSEC in a way that conflicts with custom nameservers, stop and re-read current provider guidance instead of guessing which DS it publishes.

## Adding another registrar

Do not claim support from generic familiarity. Add an adapter only after:

- current official documentation or authenticated UI is inspected,
- read and write operations are distinguished,
- nameserver and DS rollback paths are tested or marked `missing evidence`,
- secret and 2FA behavior is documented without capturing credentials,
- trigger and output cases cover provider-specific failure modes.

Until then, route the request outside this Skill or produce a precise human handoff for the exact visible mutation and require provider confirmation plus public readback.
